# AGENTS.md

Постоянные правила работы агента в этом репозитории. Они действуют в каждой сессии.
Описание проекта, источников данных и требований лежит в `BRIEF.md`. Прочитай его целиком перед началом работы.

## Проект в одной строке

Бэкенд-инфраструктура данных для сервиса ИИ-анализа российских юрлиц и ИП (поиск, карточка, финансы, налоги, МСП, источники). После явного разрешения владельца этапы 10–11 из `TODO-2.md` добавляют внутренний слой инструментов и локального CLI-агента.

## Обязательный стек

- Backend: Go + Gin.
- БД: PostgreSQL.
- Frontend: Next.js, на текущем этапе не реализуется.
- Всё остальное (библиотеки, структура папок, схема БД) выбираешь и обосновываешь сам.

## Две фазы и гейт между ними

**Фаза A: Research & Architecture Proposal.**
- Ничего не изменяй в проекте: не создавай файлы, не правь код, не добавляй зависимости, не запускай миграции, не начинай реализацию.
- Разрешено: читать файлы, изучать репозиторий и документацию, безопасные диагностические команды, которые не меняют состояние проекта.
- Результат: единый архитектурный документ в формате из раздела «Формат результата Фазы A» в `BRIEF.md`.
- После документа остановись и жди явного подтверждения. Отсутствие возражений подтверждением не считается.

**Фаза B: Implementation.**
- Начинается только после явного разрешения.
- Реализуй согласованный план по задачам, запускай тесты, проверяй результат.
- Если нужна существенная смена согласованной архитектуры, сначала объясни проблему и предложи корректировку.
- Не начинай задачи из несогласованных этапов.

## Жёсткие запреты

- Не добавляй Redis, очереди сообщений, микросервисы, векторные БД и прочее «на будущее». Только при конкретной технической необходимости с обоснованием.
- По отдельному разрешению владельца на этапе 10 разрешён внутренний Tool Calling для пяти операций этапа 9. На этапе 11 разрешён локальный CLI-агент с одним LLM-провайдером и настройкой ключа и модели из окружения.
- По отдельному разрешению владельца этап 15 допускает публичный Go API чата из TODO-2.md с Bearer-сессией, PostgreSQL и одним настроенным LLM-провайдером. Публичный деплой и этап 16 требуют отдельного согласования.
- За рамками этих исключений запрещена реализация ИИ-агента и LLM-интеграций, включая публичный API агента и продуктовую интеграцию. Роутер LLM, управление API-ключами LLM, MCP и интеграции ГИР БО, КАД Арбитр, Федресурс, ФССП, ЕИС Закупки допускаются только на уровне исследования и проектирования.
- Не обходи CAPTCHA, не маскируй запросы, не обходи rate limiting.
- Не парси HTML, если есть официальная машиночитаемая выгрузка.
- Не загружай многогигабайтные архивы целиком в память.

## Честность данных

- Не выдавай предположения за подтверждённые факты. Для существенных утверждений давай ссылки на документацию.
- Если интернет недоступен, прямо помечай непроверенные предположения.
- Не считай ссылки из задания гарантированно рабочими URL для скачивания. Проверяй, что реально доступно.
- Бесплатные выгрузки ФНС не равны полной базе ЕГРЮЛ/ЕГРИП. Не проектируй систему так, будто в них есть все компании.
- Не утверждай наличие данных, которых нет в подключённых источниках.
- Не подменяй молча данные одного источника данными другого при противоречиях.

## Инженерные принципы

- Простота важнее «масштабируемости на вырост». Критикуй исходные предположения, если есть решение проще.
- Идентификаторы (ИНН, ОГРН, ОГРНИП) хранятся строками. Отсутствие показателя не равно нулю.
- Каждый показатель хранит происхождение (источник) и дату актуальности.
- Секреты не хранятся в коде. Внутренние операции импорта не публичные.
- Тесты не должны требовать платных API.

## Где что лежит

- `docs/ARCHITECTURE.md`: появится после утверждения плана (его сохраняешь ты в начале Фазы B).
- `TODO.md`: создаётся в начале Фазы B из утверждённого плана, дальше отмечай в нём прогресс.
