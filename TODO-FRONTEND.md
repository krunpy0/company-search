# Этап 16. План фронтенда

План детализирует [этап 16](TODO-2.md#-16-минимальный-фронтенд-с-веб-чатом). Каждый блок заканчивается сценарием для ручной проверки. Реализация начинается после приёмки этапа 15 и отдельного разрешения владельца. Деплой относится к этапу 17.

- **В работе этапа 16** — пункты со штатным API или достаточными данными на фронтенде.
- **Нет API** — зафиксировать недостающий контракт. Если экран нужен в текущей сборке, предусмотреть состояние недоступности без имитации успешной операции. Изменения Go API и БД вне объёма этапа.
- **-PLACEHOLDER** — сверстать состояние без интеграции. Демонстрационные успех и ошибка доступны только в сценариях проверки интерфейса.
- **-LATER** — оставить в плане до явного снятия тега владельцем.

Использовать тёмные поверхности, красный акцент, Onest и CSS-токены из [DESIGN.md](design/design-reference/DESIGN.md). Сверять chat-композицию по двум макетам, размеры и состояния управления по дизайн-системе. На мобильном боковая панель открывается как выдвижная, форма остаётся доступной с открытой клавиатурой. Остальные экраны используют те же формы, меню и диалоги. Наименования компаний, тексты ответов, цены и функции из макетов считать демонстрационными до подтверждения данных.

Расширять существующий Next.js App Router в `frontend/`. Публичные маршруты включают лендинг, вход, регистрацию, помощь и документы. Защищённые маршруты включают поиск, карточку компании, новый чат и чат по ID. Настройки, тарифы и действия с диалогом открываются поверх рабочего экрана. Сгенерировать типизированный клиент из [OpenAPI](backend/openapi.yaml), зафиксировать команду обновления и выделить единое преобразование кодов ошибок в состояния UI.

Предлагаемая схема сессии — серверные обработчики Next.js одного origin хранят Bearer в HttpOnly cookie и передают его Go API. Использовать срок `expires_at`, Secure для HTTPS, SameSite и проверку origin для изменений состояния. Исключить кэширование персональных ответов. Детали реализации сверить с локальной документацией Next.js по [правилам фронтенда](frontend/AGENTS.md).

Готово, когда новый пользователь регистрируется, входит, сохраняет сессию после перезагрузки и выходит. Истёкшая сессия возвращает на вход, предыдущая история очищается из состояния интерфейса при смене аккаунта.
