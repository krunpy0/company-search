# Локальный запуск бэкенда

Из каталога `backend` в PowerShell. Нужны Go с поддержкой версии из `go.mod` и Docker Compose.

```powershell
$env:POSTGRES_PASSWORD = [guid]::NewGuid().ToString('N')
$env:DATABASE_URL = "postgres://company_search:${env:POSTGRES_PASSWORD}@127.0.0.1:5432/company_search?sslmode=disable"
docker compose up -d --wait
go run ./cmd/migrate
go run ./cmd/api
```

При повторном запуске с тем же томом PostgreSQL используй пароль, с которым том был создан. `HTTP_ADDR` задаёт адрес сервера, по умолчанию `:8080`. `sslmode=disable` подходит для локального стенда.

После запуска оба маршрута возвращают `204`. При остановленной PostgreSQL `/readyz` возвращает `503`, а `/healthz` продолжает возвращать `204`.

```powershell
curl.exe -i http://localhost:8080/healthz
curl.exe -i http://localhost:8080/readyz
go test ./...
```

## Ручной импорт доходов и расходов ФНС

После миграций запусти команду с датой проверенного выпуска.

```powershell
go run ./cmd/import -published-on 2026-10-25
```

Можно передать `-archive <путь>` для локальной копии того же официального ZIP. Команда записывает SHA-256, дату выпуска, год отчётности, дату наблюдения, имя XML и идентификатор документа. Опубликованный выпуск года указан в `published_releases`. Сведения текущей версии выбираются соединением с этой таблицей по `release_id`.

Импорт пишет пакетами внутри одной транзакции PostgreSQL. При ошибке или завершении процесса транзакция откатывается. Следующий запуск отмечает оставшуюся попытку как прерванную. Прогресс виден в логах каждые 100 000 загруженных строк. Повтор с тем же хешем сохраняет запись о попытке и использует существующий выпуск.

Для временного архива скачивания выдели до 512 МиБ в системном временном каталоге. XML читается непосредственно из ZIP. Поддерживается схема `4.01`.

## Ручной импорт реестра МСП

После миграций используй дату выпуска, проверенного по [паспорту ФНС](https://www.nalog.gov.ru/opendata/7707329152-rsmp/). Команда поддерживает схему 4.06 и шаблон имени архива с датой в порядке ДДММГГГГ.

```powershell
go run ./cmd/import -dataset rsmp -published-on 2026-11-10
go run ./cmd/import -dataset rsmp -published-on 2026-11-10 -archive <путь-к-полному-официальному-ZIP>
```

Скачивание ограничено 3 ГиБ и 30 минутами на попытку. Проверь свободное место в каталоге `$env:TEMP` и на диске PostgreSQL. Ручной `-archive` предназначен для полной доверенной копии официального файла. Проверки ZIP и счётчиков XML обнаруживают повреждение файлов внутри архива. Отдельного манифеста ФНС для проверки состава ZIP команда не использует.

Этап записи использует временную таблицу в транзакции и пакетный `COPY`. Два регистрационных номера по одному ИНН сохраняются раздельно. Дубли регистрации в одном срезе и конфликт ИНН по одному ОГРН или ОГРНИП приводят к откату. Численность сохраняется с исходным годом по правилам паспорта, пропуск остаётся `NULL`.

Для чтения текущего МСП соединяй `sme_observations` с `published_releases` по `release_id` и фильтруй `dataset_code='rsmp' AND period_key='current'`. Отсутствие строки означает отсутствие записи в выбранном выпуске. Старые наблюдения сохраняются, а загрузка старого выпуска не переключает указатель назад. Сведения из прежнего среза сами по себе не подтверждают текущее членство в МСП или регистрационный статус.

## Локальный API компаний

Примени миграции и импортируй оба набора P0. Миграция поиска строит индексы по названиям. На уже заполненной базе она блокирует запись в индексируемые таблицы до завершения. Запускай её вне окна импорта.

```powershell
go run ./cmd/migrate
go run ./cmd/api
```

Найди организацию и используй `id` из ответа для карточки, финансов и источников.

```powershell
curl.exe "http://localhost:8080/v1/companies?q=3907056353"
curl.exe "http://localhost:8080/v1/companies/reg:1073906000376"
curl.exe "http://localhost:8080/v1/companies/reg:1073906000376/financials?year=2025"
curl.exe "http://localhost:8080/v1/companies/reg:1073906000376/sources"
```

Поиск по названию принимает от 3 до 200 символов. Точное совпадение без учёта регистра идёт первым. При оценке близости опускаются распространённые начальные обозначения ООО и АО. В результаты попадают названия с триграммным сходством от 0,6. Передай `next_cursor` вместе с теми же `q`, `mode` и `kind` для следующей страницы. При `409 stale_cursor` начни с первой страницы.

Регистрационные ключи показывают наблюдение МСП. Статус и дата регистрации требуют отдельного источника. Финансовые суммы отражают опубликованные сведения по ИНН и возвращаются десятичными строками. По `source_ref` можно найти паспорт и дату выпуска в `sources`. У каждого наблюдения есть дата состояния и идентификатор исходного XML-документа.

На стенде с выпусками из этапов 2 и 3 выполни проверку маршрутов и сверку финансовых полей с PostgreSQL.

```powershell
$env:COMPANY_API_TEST_DATABASE_URL = $env:DATABASE_URL
go test -count=1 ./internal/httpapi
```

## DaData

По умолчанию API читает только PostgreSQL. Для согласованной среды задай `DADATA_ENABLED=true`, `DADATA_TOKEN` и положительный `DADATA_DAILY_BUDGET` через окружение или локальный `.env`. Выдели ключ для этого процесса и задай бюджет в пределах его квоты. Проверь разрешённую аудиторию и условия показа реквизитов до включения.

Клиент ждёт ответ до 1,5 секунды и отправляет не более одного запроса в секунду. Суточный бюджет сбрасывается в полночь по Москве и хранится в памяти процесса. Перезапуск обнуляет счётчик. Несколько экземпляров ведут независимые счётчики. При `429` клиент учитывает `Retry-After`. API отдаёт локальные данные с предупреждением при недоступности DaData.

На первой странице поиска по названию DaData возвращает до 20 отдельных `external_suggestions`. В точном поиске первая страница может дополнительно содержать кандидатов из DaData. `limit` и `next_cursor` относятся к PostgreSQL. Сведения DaData идут в объекте `dadata` с источником и временем получения. Дата последнего изменения выводится отдельно, дата среза остаётся неизвестной. Наблюдения ФНС сохраняют своё происхождение. Ответы DaData живут только в рамках запроса и отправляются с `Cache-Control: no-store`.

Локальные тесты клиента запускаются без ключа командой `go test ./internal/dadata`. Проверка объединения через Gin входит в тест `TestPublishedCompanyAPI` на стенде с выпусками ФНС.
