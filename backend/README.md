# Локальный запуск бэкенда

Из каталога `backend` в PowerShell. Нужны Go с поддержкой версии из `go.mod` и Docker Compose.

```powershell
$env:POSTGRES_PASSWORD = [guid]::NewGuid().ToString('N')
$env:DATABASE_URL = "postgres://company_search:${env:POSTGRES_PASSWORD}@127.0.0.1:5432/company_search?sslmode=disable"
docker compose up -d --wait
go run ./cmd/migrate
go run ./cmd/api
```

При повторном запуске с тем же томом PostgreSQL используй пароль, с которым том был создан. `HTTP_ADDR` задаёт адрес сервера, по умолчанию `:8080`. `sslmode=disable` подходит для локального стенда. По умолчанию `./cmd/api` применяет встроенные миграции при старте; чтобы отключить автомиграцию (например, при запуске под ролью `company_api`), задай `AUTO_MIGRATE=false`.

### Восстановление пароля через Resend

Примени миграции до версии `017` включительно и задай переменные окружения для Go API.

| Переменная | Значение |
| --- | --- |
| `COMPANY_APP_ORIGIN` | Публичный HTTPS-адрес фронтенда без пути и завершающего слеша |
| `RESEND_API_KEY` | Ключ Resend с правом отправки писем |
| `PASSWORD_RESET_FROM` | Адрес отправителя на подтверждённом домене Resend |

На фронтенде задай тот же `COMPANY_APP_ORIGIN` и направь `COMPANY_API_URL` на Go API. Оставь отслеживание кликов Resend выключенным для домена отправителя, чтобы ссылка с токеном вела напрямую на страницу восстановления. См. [Resend API](https://resend.com/docs/api-reference/emails/send-email) и [настройки отслеживания Resend](https://resend.com/blog/introducing-custom-tracking-domain).

Ссылка действует 30 минут. Пока она действительна, повторный запрос повторно письмо не отправляет. При успешном сбросе API отзывает все сессии аккаунта. Если переменные для Resend отсутствуют, запрос ссылки вернёт `503`.

Для защиты от частых запросов в `./cmd/api` встроен token-bucket rate limiter (маршруты `/healthz` и `/readyz` не ограничиваются). По умолчанию включён (`RATE_LIMIT_ENABLED=true`): общий лимит по IP на `/v1/*` (`RATE_LIMIT_IP_RPM=240`, `RATE_LIMIT_IP_BURST=120`), строгий лимит по IP на `/v1/auth/register` и `/v1/auth/login` (`RATE_LIMIT_AUTH_RPM=10`, `RATE_LIMIT_AUTH_BURST=15`), лимит по `user_id` для авторизованных маршрутов (`/v1/account/*`, `/v1/companies/*`, `/v1/chat/dialogues/*`, `/v1/auth/logout`: `RATE_LIMIT_API_RPM=120`, `RATE_LIMIT_API_BURST=60`) и отдельный лимит на отправку сообщений чата (`RATE_LIMIT_CHAT_RPM=20`, `RATE_LIMIT_CHAT_BURST=10`). Максимальное число отслеживаемых ключей на уровень задаётся `RATE_LIMIT_MAX_ENTRIES` (по умолчанию `16384`). При превышении API отвечает `429 rate_limited` с заголовками `Retry-After` и `X-RateLimit-*`. По умолчанию заголовки `X-Forwarded-For` / `X-Real-IP` не доверяются; при работе за обратным прокси укажи доверенные адреса или подсети через `TRUSTED_PROXIES` (через запятую, например `127.0.0.1,::1`).

После запуска оба маршрута возвращают `204`. При остановленной PostgreSQL `/readyz` возвращает `503`, а `/healthz` продолжает возвращать `204`.

```powershell
curl.exe -i http://localhost:8080/healthz
curl.exe -i http://localhost:8080/readyz
go test ./...
```

## Ручной импорт доходов и расходов ФНС

После миграций запусти команду с датой проверенного выпуска.

```powershell
go run ./cmd/import -published-on 2026-10-25
```

Можно передать `-archive <путь>` для локальной копии того же официального ZIP. Команда записывает SHA-256, дату выпуска, год отчётности, дату наблюдения, имя XML и идентификатор документа. Опубликованный выпуск года указан в `published_releases`. Сведения текущей версии выбираются соединением с этой таблицей по `release_id`.

Импорт пишет пакетами внутри одной транзакции PostgreSQL. При ошибке или завершении процесса транзакция откатывается. Следующий запуск отмечает оставшуюся попытку как прерванную. Прогресс виден в логах каждые 100 000 загруженных строк. Повтор с тем же хешем сохраняет запись о попытке и использует существующий выпуск.

Для временного архива скачивания выдели до 512 МиБ в системном временном каталоге. XML читается непосредственно из ZIP. Поддерживается схема `4.01`.

## Ручной импорт реестра МСП

После миграций используй дату выпуска, проверенного по [паспорту ФНС](https://www.nalog.gov.ru/opendata/7707329152-rsmp/). Команда поддерживает схему 4.06 и шаблон имени архива с датой в порядке ДДММГГГГ.

```powershell
go run ./cmd/import -dataset rsmp -published-on 2026-11-10
go run ./cmd/import -dataset rsmp -published-on 2026-11-10 -archive <путь-к-полному-официальному-ZIP>
```

Скачивание ограничено 3 ГиБ и 30 минутами на попытку. Проверь свободное место в каталоге `$env:TEMP` и на диске PostgreSQL. Ручной `-archive` предназначен для полной доверенной копии официального файла. Проверки ZIP и счётчиков XML обнаруживают повреждение файлов внутри архива. Отдельного манифеста ФНС для проверки состава ZIP команда не использует.

Этап записи использует временную таблицу в транзакции и пакетный `COPY`. Два регистрационных номера по одному ИНН сохраняются раздельно. Дубли регистрации в одном срезе и конфликт ИНН по одному ОГРН или ОГРНИП приводят к откату. Численность сохраняется с исходным годом по правилам паспорта, пропуск остаётся `NULL`.

Для чтения текущего МСП соединяй `sme_observations` с `published_releases` по `release_id` и фильтруй `dataset_code='rsmp' AND period_key='current'`. Отсутствие строки означает отсутствие записи в выбранном выпуске. Старые наблюдения сохраняются, а загрузка старого выпуска не переключает указатель назад. Сведения из прежнего среза сами по себе не подтверждают текущее членство в МСП или регистрационный статус.

## Локальный API компаний

Примени миграции и импортируй оба набора P0. Миграция поиска строит индексы по названиям. На уже заполненной базе она блокирует запись в индексируемые таблицы до завершения. Запускай её вне окна импорта.

```powershell
go run ./cmd/migrate
go run ./cmd/api
```

Создай локальный аккаунт через API и получи токен сессии. При повторном входе используй пароль того же аккаунта.

```powershell
$api = 'http://localhost:8080'
$testID = [guid]::NewGuid().ToString('N')
$credentials = @{
	email = "test-$testID@example.invalid"
	password = [guid]::NewGuid().ToString('N')
} | ConvertTo-Json
Invoke-RestMethod "$api/v1/auth/register" -Method Post -ContentType 'application/json' -Body $credentials
$session = Invoke-RestMethod "$api/v1/auth/login" -Method Post -ContentType 'application/json' -Body $credentials
$headers = @{ Authorization = "Bearer $($session.access_token)" }
```

API возвращает `user_id` при регистрации. Пароль должен занимать от 12 до 72 байт в UTF-8. При входе API выдаёт токен на 24 часа и возвращает дату истечения в `expires_at`.

Выполни поиск с токеном. Подставь `id` из результата вместо указанного в примерах ключа.

```powershell
Invoke-RestMethod "$api/v1/companies?q=3907056353" -Headers $headers
Invoke-RestMethod "$api/v1/companies/reg:1073906000376" -Headers $headers
Invoke-RestMethod "$api/v1/companies/reg:1073906000376/financials?year=2025" -Headers $headers
Invoke-RestMethod "$api/v1/companies/reg:1073906000376/sources" -Headers $headers
```

Заверши сессию через `Invoke-RestMethod "$api/v1/auth/logout" -Method Post -Headers $headers`. Запрос с отозванным или истёкшим токеном возвращает `401`.

Поиск по названию принимает от 3 до 200 символов. Точное совпадение без учёта регистра идёт первым. При оценке близости опускаются распространённые начальные обозначения ООО и АО. В результаты попадают названия с триграммным сходством от 0,6. Передай `next_cursor` вместе с теми же `q`, `mode` и `kind` для следующей страницы. При `409 stale_cursor` начни с первой страницы.

Регистрационные ключи показывают наблюдение МСП или спецрежимов ИП. Статус и дата регистрации требуют отдельного источника. Финансовые суммы отражают опубликованные сведения по ИНН и возвращаются десятичными строками. По `source_ref` можно найти паспорт и дату выпуска в `sources`. У каждого наблюдения есть дата состояния и идентификатор исходного XML-документа.

Карточка возвращает массив `headcounts`. Если МСП и отдельная выгрузка публикуют численность за один год, в массиве будут оба наблюдения со своими датами и источниками. Ноль передаётся числом, пропуск — отсутствием наблюдения.

`GET /v1/companies/{id}/taxes?section=regimes&as_of=2026-10-01` выбирает точный срез. Без `as_of` API выбирает последний загруженный срез для вида субъекта. `not_loaded` означает отсутствие запрошенного среза в базе, `not_published` — отсутствие записи субъекта в выбранном срезе.

Если ИНН у одного ОГРНИП расходится в спецрежимах и текущем срезе МСП, импорт переносит наблюдение спецрежимов в карантин. Карточка и `/taxes` показывают `identity_conflict`. Спорные коды и второй ИНН остаются в PostgreSQL для сверки. Метаданные выпуска содержат `quarantined_count`, если часть записей исключена из выдачи.

### Проверка ролей PostgreSQL

Создай отдельные login-роли `company_api` и `company_importer` без `SUPERUSER` и членства в роли владельца. После миграций примени [настройку прав](db-roles.sql) под владельцем объектов или администратором. Укажи `DATABASE_URL` соответствующей роли при запуске API и импортера. Миграции запускай под владельцем объектов.

```powershell
psql $env:DATABASE_URL -f db-roles.sql
```

Выполни запрос под учётными данными API и импортера. Для API оба значения доступа к `accounts` должны быть `true`, для импортера оба должны быть `false`.

```sql
SELECT current_user, r.rolsuper, r.rolcreaterole,
       has_schema_privilege(current_user, n.oid, 'USAGE') AS can_use_accounts,
       has_table_privilege(current_user, c.oid, 'SELECT') AS can_read_users,
       has_database_privilege(current_database(), 'TEMP') AS can_stage
FROM pg_roles AS r
CROSS JOIN pg_namespace AS n
JOIN pg_class AS c ON c.relnamespace = n.oid
WHERE r.rolname = current_user AND n.nspname = 'accounts' AND c.relname = 'users';
```

Импортеру нужен `TEMP` для промежуточных таблиц. Роль API читает каталог ФНС и записывает данные сессий и квот. Общая роль локального Compose имеет `SUPERUSER`. Изоляцию проверяй под отдельными ролями.

Для сквозной проверки сессий и квот создай отдельную пустую БД `stage14_test`, примени миграции и настройку прав. Задай `COMPANY_ACCOUNTS_TEST_ADMIN_URL` для владельца и `COMPANY_ACCOUNTS_TEST_API_URL` для роли API. Тест очищает таблицы схемы `accounts` в этой БД и использует подменный внешний источник.


## DaData

По умолчанию API читает только PostgreSQL. Для согласованной среды задай `DADATA_ENABLED=true`, `DADATA_TOKEN` и положительный `EXTERNAL_API_DAILY_BUDGET` через окружение или локальный `.env`. Выбери бюджет в пределах квоты ключа. Проверь разрешённую аудиторию и условия показа реквизитов до включения.

`EXTERNAL_API_DAILY_BUDGET` ограничивает число исходящих вызовов на ключ поставщика. У экземпляров API и CLI с одним ключом и одной БД общий счётчик. Задай им одинаковый бюджет. PostgreSQL хранит счётчик после перезапуска. Суточное окно меняется в полночь по Москве. Для одного ключа между резервированиями проходит не меньше секунды. При `429` от DaData клиент учитывает `Retry-After`. Тайм-аут ответа составляет 1,5 секунды.

`USER_EXTERNAL_API_DAILY_BUDGET` ограничивает внешние вызовы пользователя за московские сутки. Значение по умолчанию равно 5. Каждая сессия одного аккаунта расходует общий бюджет. Перед исходящим запросом API атомарно резервирует единицу пользовательской квоты и квоты ключа. При отсутствии запаса API пропускает вызов DaData и возвращает доступные сведения ФНС. Код `user_external_api_budget_exhausted` в `warnings` указывает на исчерпание бюджета пользователя. Запросы, обслуженные из PostgreSQL, доступны и после исчерпания внешней квоты.

На первой странице поиска по названию DaData возвращает до 20 отдельных `external_suggestions`. В точном поиске первая страница может дополнительно содержать кандидатов из DaData. `limit` и `next_cursor` относятся к PostgreSQL. Сведения DaData идут в объекте `dadata` с источником и временем получения. Дата последнего изменения выводится отдельно, дата среза остаётся неизвестной. Наблюдения ФНС сохраняют своё происхождение. Ответы DaData живут только в рамках запроса и отправляются с `Cache-Control: no-store`.

На закрытом стенде включи `DADATA_REGISTRY_DETAILS_ENABLED=true` вместе с `DADATA_ENABLED=true`. В точном поиске и карточке объект `dadata` дополнительно содержит `manager` (имя или наименование, должность и дата вступления при наличии) для ЮЛ либо `residence_city` для ИП. Поля наследуют источник и время получения объекта. DaData передаёт дату последнего изменения записи и иногда дату вступления руководителя в должность. Эти даты не обозначают дату проверки остальных полей. Если поставщик не вернул значение, поле отсутствует. При несовпадении идентификаторов API исключает спорную запись и возвращает `provider_identity_conflict`. CLI и подсказки по названию используют прежний набор полей.

Для ручной проверки на закрытом стенде с разрешёнными данными открой `GET /v1/companies?q=<ОГРН или ОГРНИП>`, затем `GET /v1/companies/reg:<ОГРН или ОГРНИП>` для тестового ЮЛ и ИП. Сверь поля, источник и даты с образцами.

Локальные тесты клиента запускаются без ключа командой `go test ./internal/dadata`. Проверка объединения через Gin входит в тест `TestPublishedCompanyAPI` на стенде с выпусками ФНС.

### Импорт платежей и задолженности

После `go run ./cmd/migrate` загрузите выпуски из каталога `backend`:

```powershell
go run ./cmd/import -dataset paytax -published-on 2026-04-01
go run ./cmd/import -dataset debtam -published-on 2026-10-25
```

Флаг `-archive <путь>` позволяет использовать сохранённый официальный ZIP. Платежи публикуются по отчётному году, а задолженность по дате состояния из XML.

- `GET /v1/companies/{id}/taxes?section=payments&year=2025` возвращает платежи за указанный год. Без `year` доступны все загруженные годы.
- `GET /v1/companies/{id}/taxes?section=debts&as_of=2026-10-01` возвращает задолженность на указанную дату. Без `as_of` выбирается последний загруженный срез.
- Для обоих разделов `limit` задаёт размер страницы от 1 до 100. Передавайте `next_offset` ответа как `offset` в следующем запросе с теми же фильтрами. После смены опубликованного выпуска начните с первой страницы.
- Суммы передаются десятичными строками в рублях. Неопубликованный компонент долга передаётся как `null`, а опубликованный ноль как строка с нулём. Показатели относятся к налогоплательщику по ИНН. Для ИП эти два набора дают `not_applicable`.

Запустите сквозную проверку после загрузки двух выпусков и выпуска спецрежимов юрлиц `snr` от 25.10.2026:

```powershell
$env:COMPANY_API_STAGE7_TEST_DATABASE_URL = $env:DATABASE_URL
go test ./internal/httpapi -run '^TestPublishedMoneyTaxes$' -count=1
```

## Расписание и восстановление выпусков ФНС

`import -check -dataset <код>` проверяет одну последнюю ожидаемую дату по Москве. Если выпуск уже загружен, команда завершится без запроса к ФНС. Для даты вне обычного графика сверьте официальный паспорт и передайте `-published-on YYYY-MM-DD`. [График ФНС для налоговых наборов](https://www.nalog.gov.ru/rn11/news/activities_fts/16631320/)

| Набор | Ожидаемая дата ZIP | Что меняется в выдаче |
|---|---|---|
| [`rsmp`](https://www.nalog.gov.ru/opendata/7707329152-rsmp/) | 10-е число | Новый полный срез заменяет текущий. |
| [`revexp`](https://www.nalog.gov.ru/rn27/opendata/7707329152-revexp/), [`sshr2019`](https://www.nalog.gov.ru/opendata/7707329152-sshr2019/) | 25-е число | Новый выпуск заменяет версию своего отчётного года. |
| [`paytax`](https://www.nalog.gov.ru/opendata/7707329152-paytax/) | 1 апреля | Публикуется отчётный год. Предыдущие годы остаются доступны. |
| [`debtam`](https://www.nalog.gov.ru/opendata/7707329152-debtam/), [`snr`](https://www.nalog.gov.ru/opendata/7707329152-snr/), [`snrip`](https://www.nalog.gov.ru/opendata/7707329152-snrip/) | 25-е число | Публикуется срез на дату состояния из XML. Он заменяет сведения только для этой даты. |

### Запуск из cron

1. После миграций соберите `go build -o company-import ./cmd/import` в каталоге `backend`. Установите бинарник в `/opt/company-search/company-import`.
2. Под учётной записью импортера создайте закрытые каталоги `/var/lib/company-search/import-tmp` и `/var/lib/company-search` для временных архивов, блокировки и журнала. В `/etc/company-search/import.env` с доступом только для оператора и импортера задайте `export DATABASE_URL='…'` с учётными данными для записи. API может работать с отдельной ролью чтения.
3. Добавьте строку в пользовательский crontab импортера. Она выполняет проверки последовательно в 04:15 по времени хоста. Настройте ротацию `import.log` и оповещение по ошибкам в журнале.

```cron
15 4 * * * /usr/bin/flock -n /var/lib/company-search/import.lock /bin/sh -c '. /etc/company-search/import.env || exit 1; export TMPDIR=/var/lib/company-search/import-tmp; status=0; for dataset in rsmp revexp sshr2019 paytax debtam snr snrip; do /opt/company-search/company-import -check -dataset "$dataset" || status=1; done; exit "$status"' >> /var/lib/company-search/import.log 2>&1
```

Cron и ручной импорт используют одну блокировку PostgreSQL на набор. `release_missing` означает HTTP 404 или 410 по ожидаемому URL. Сверьте дату, путь и XSD с паспортом. `unknown_schema` означает неподдерживаемую версию XML в полученном ZIP. Обновите адаптер только после проверки новой схемы. Если ФНС изменила имя ZIP вместе с XSD, первым сигналом будет `release_missing`. Сбой оставляет указатель на прежний выпуск.

```sql
SELECT dataset_code, id, started_at, status, error_code, release_id, rows_seen
FROM import_runs ORDER BY id DESC LIMIT 30;
```

При обрыве PostgreSQL откатывает незавершённую загрузку и очищает временные таблицы. Следующая проверка под блокировкой отмечает зависшую попытку как `interrupted`. После принудительного завершения процесса на диске может остаться `.part`. Удаляйте его только из выделенного каталога, когда задачи импорта остановлены.

Под первый полный МСП выделите около 10 ГиБ свободного места под данные PostgreSQL и до 3 ГиБ под ZIP. При следующих импортах учитывайте накопленные выпуски, индексы и резервные копии. История выпусков пока сохраняется целиком. Для платежей, задолженности и режимов отдельной оценки пикового места в этапе 8 нет. [Замеры P0](../TODO.md#замеры-p0)

### Откат и восстановление из резервной копии

Сначала найдите активный ID и доступные версии. Сверьте дату выпуска и период перед переключением.

```sql
SELECT r.dataset_code, r.period_key, r.id, r.published_on,
       EXISTS (SELECT 1 FROM published_releases p WHERE p.release_id = r.id) AS active
FROM releases r WHERE r.status = 'published'
ORDER BY r.dataset_code, r.period_key, r.published_on DESC;
```

```sh
company-import -dataset revexp -rollback-current 42 -restore-release 41
company-import -dataset debtam -rollback-current 57
```

Первый пример переключает выпуск внутри того же периода. Второй снимает публикацию с даты задолженности, если в базе доступен более ранний срез. Запрос без даты читает оставшийся последний срез, а запрос по снятой дате сообщает `not_loaded`. Оба варианта проверяют ожидаемый активный ID под блокировкой. Строки выпуска сохраняются. Проверка расписания пропускает уже загруженные выпуски, включая снятый с публикации. Чтобы отменить переключение внутри одного периода, поменяйте ID местами. После снятия отдельной даты для возврата её указателя требуется восстановление из бэкапа или операторская транзакция с блокировкой набора.

Храните резервные копии в закрытом хранилище вне диска PostgreSQL. В примере `BACKUP_DSN` указывает на БД с правом чтения всех таблиц, а `RESTORE_DSN` указывает на отдельную пустую БД. Используйте клиентские утилиты PostgreSQL 17.

```sh
umask 077
pg_dump --format=custom --file=company-search.dump "$BACKUP_DSN"
pg_restore --exit-on-error --single-transaction --no-owner --no-privileges \
  --dbname="$RESTORE_DSN" company-search.dump
```

Сравните указатели и число строк по выпускам с исходной БД. Запустите API с `DATABASE_URL` восстановленной базы и проверьте выдачу выбранных ИНН. Перед переключением рабочей среды примените её роли и права доступа.

## API чата

При штатной остановке API даёт активным HTTP-запросам до 130 секунд на завершение. Если процессом управляет Docker, systemd или другой менеджер, его тайм-аут принудительной остановки должен быть больше 130 секунд.

Запусти миграции и примени `db-roles.sql` под владельцем базы. Запусти API под ролью `company_api` с `AUTO_MIGRATE=false`. Для отправки сообщений задай `CHAT_ENABLED=true`, `OPENAI_BASE_URL` и `OPENAI_MODEL`. Если сервер модели требует ключ, задай `OPENAI_API_KEY`. При выключенной модели создание и чтение диалогов доступны, отправка возвращает `503 model_unavailable`.

Для каждого запроса передай `Authorization: Bearer <access_token>`. Получи токен через `POST /v1/auth/login`.

1. Создай диалог через `POST /v1/chat/dialogues`. Передай `{}` или объект с полем `registration` и ОГРН или ОГРНИП.
2. Отправь `{"content":"Есть ли налоговая задолженность?"}` через `POST /v1/chat/dialogues/{id}/messages`. API возвращает сохранённый ход и ответ целиком. Если в `answer.candidates` есть варианты, отправь один из номеров следующим сообщением. Агент повторит исходный вопрос с выбранной регистрацией.
3. Открой список через `GET /v1/chat/dialogues` и историю через `GET /v1/chat/dialogues/{id}/messages`. Списки идут от новых к старым. Для следующей страницы передай `next_before_id` как `before_id`.

Ход хранит вопрос, ответ, наблюдения и их `source_ref`. Дата состояния доступна в `records[].as_of` при наличии. Для уточнения модель получает до четырёх предыдущих ходов общим объёмом до 6000 байт. Ответы со сведениями внешних поставщиков повторно не передаются. Факты агент заново запрашивает через инструменты. Выбранная регистрация сохраняется в диалоге и применяется к следующим вопросам.

На пользователя выделяется пять принятых сообщений за московские сутки. Ответ модели с ошибкой расходует попытку. Отказ по доступу, недействительный выбор и параллельное сообщение в тот же диалог попытку не расходуют. `CHAT_DAILY_TOKEN_BUDGET` задаёт дневной бюджет токенов на пользователя. По умолчанию он равен 125 000. Перед каждым вызовом API резервирует оценку входа и максимум ответа. При получении `usage` API учитывает сообщённый расход. При отсутствии `usage` резерв остаётся списанным. Ход ограничен двумя минутами и шестью вызовами модели.

- `401 invalid_session` означает, что нужна действующая сессия. `404 dialogue_not_found` возвращается и для чужого диалога.
- `409 turn_in_progress` означает, что в диалоге уже обрабатывается сообщение.
- `429 message_budget_exhausted` или `429 token_budget_exhausted` означают, что исчерпан соответствующий дневной лимит.
- `503 model_unavailable` означает, что модель выключена или временно недоступна.

Вопросы и результаты инструментов передаются серверу модели, указанному в `OPENAI_BASE_URL`. Название диалога генерируется отдельным вызовом Chat Completions без инструментов параллельно с обработкой первого вопроса. Для отдельного провайдера заполни в бэкендовом `.env` все три переменные:

```dotenv
CHAT_TITLE_OPENAI_API_KEY=
CHAT_TITLE_OPENAI_BASE_URL=
CHAT_TITLE_OPENAI_MODEL=
```

Если хотя бы одна переменная пуста, используются основные настройки `OPENAI_*`. Провайдер названий получает первый вопрос. Вызов расходует общий дневной токеновый бюджет чата. При сбое генерации ответ сохраняется, а в списке остаётся регистрация или дата создания.

Для чата DaData по умолчанию выключена. Включай `CHAT_DADATA_ENABLED=true` вместе с `DADATA_ENABLED=true`, только если условия поставки разрешают показ пользователям API, передачу выбранной модели и хранение сведений в истории. Чат использует квоты DaData этапа 14. Наборы ФНС по поддержке МСП и налоговым правонарушениям подключаются через `FNS_SUPPORT_AGENT_ENABLED` и `FNS_TAX_OFFENCES_AGENT_ENABLED`.

Для проверки миграций, импорта исправленного архива, поиска, аккаунтов и чата запусти из `backend` команду `pwsh -NoProfile -File ./test-postgres.ps1`. Нужны PowerShell 7.4+ и запущенный Docker. Скрипт создаёт временный контейнер PostgreSQL с отдельными тестовыми базами, применяет миграции и права, проверяет прохождение всех выбранных тестов и удаляет контейнер после прогона.

Для отдельного запуска теста API чата создай PostgreSQL с именем базы, начинающимся на `stage15_test`. Примени миграции и `db-roles.sql`. Тест HTTP загружает фикстуру после очистки таблиц данных в этой базе. Задай `COMPANY_CHAT_TEST_ADMIN_URL` и `COMPANY_CHAT_TEST_API_URL` для ролей владельца и API. Запусти из `backend`:

```powershell

```

Модель и DaData в этих тестах подменены. [Контракт OpenAPI](openapi.yaml)

## Локальный агент

Укажи `DATABASE_URL` для базы с загруженными выпусками, `OPENAI_BASE_URL` для OpenAI-compatible API и `OPENAI_MODEL` для модели с Tool Calling. Задай `OPENAI_API_KEY`, если сервер требует Bearer-токен. Переменные можно задать в окружении или в локальном `.env`. CLI передаёт вопрос и локальные открытые данные ФНС на указанный сервер.

Чтобы CLI также получал регистрационные сведения из DaData, задай `DADATA_AGENT_ENABLED=true`, `DADATA_TOKEN` и положительный целочисленный `EXTERNAL_API_DAILY_BUDGET`. Включай этот режим, когда условия использования позволяют передавать реквизиты на сервер из `OPENAI_BASE_URL`. CLI передаёт нормализованные результаты поиска и карточки модели и хранит их в памяти текущего диалога. При использовании того же ключа и БД вызовы CLI расходуют общий с API бюджет ключа. При сбое DaData доступны локальные сведения ФНС. В ответах CLI ссылки `[dadata-N]` ведут к источнику регистрационных сведений. Время получения этих сведений выводится отдельно от даты состояния, если она известна.

Из каталога `backend` запусти команду. Пример использует тестовый ИНН из набора `fixture-v1`.

```powershell
go run ./cmd/agent "Какая задолженность по НДС у ИНН 6612025806 на 2026-10-01?"
```

Указывай базовый URL с префиксом API, например `http://localhost:8000/v1`. CLI сам добавляет `/chat/completions`. Лимиты по умолчанию — 6 запросов к модели и 24 000 байт результатов инструментов в истории вопроса. Чтобы изменить лимиты, перед вопросом укажи `-steps` и `-result-bytes`.

CLI печатает человеческий ответ модели со ссылками `[fns-N]`, датами и URL источников. Для диалога запусти `go run ./cmd/agent` без вопроса или `go run ./cmd/agent -chat "7415081779 расскажи про компанию"`. Следующие вопросы используют историю текущей сессии. `/new` очищает историю, `/exit` завершает диалог. История существует только в памяти процесса; после 100 сообщений или 256 000 байт истории нужно начать новый диалог. На весь вопрос отведено две минуты, на один запрос к модели — до 90 секунд в пределах этого времени.

Флаг `-json` включает диагностический JSON. `summary` содержит текст модели, `records` содержит полученные наблюдения с датами состояния `as_of` и источниками, включая сохранённые наблюдения сессии. Наличие записи не означает, что модель использовала её в ответе. `partial: true` означает неполный ответ; такой ход не сохраняется в истории.

Go проверяет, что ссылки `[fns-N]`, `[dadata-N]` и `[checko-N]` разрешаются в полученных наблюдениях. Даты и соответствие утверждений источникам требуют проверки, качество ответа зависит от выбранной модели.

В `findings` сохраняются состояния покрытия, предупреждения и сведения о следующей странице. Если страница помечена `truncated`, для повторной выборки начни с той же страницы и уменьши её размер. Если CLI возвращает `candidates`, введи номер из списка отдельным сообщением. В режиме диалога CLI повторит исходный вопрос для выбранной регистрации. При запуске отдельной команды передай исходный вопрос с выбранным номером.

[Воспроизводимая проверка на PostgreSQL с подменной моделью](../docs/JOURNAL.md#этап-11-локальный-cli-агент).

[Документация и тариф](https://checko.ru/integration/api) · [Условия использования](https://checko.ru/offer)

На бесплатном тарифе поставщик заявляет 100 запросов в сутки для всех методов. CLI получает бухотчётность и исполнительные производства юрлиц, а также арбитражные дела, проверки, госконтракты, историю событий, сообщения Федресурса и ЕФРСБ. Закупки запрашиваются отдельно по 44-ФЗ, 94-ФЗ и 223-ФЗ. [Финансы](https://checko.ru/integration/api/finances) · [Арбитраж](https://checko.ru/integration/api/legal-cases) · [Проверки](https://checko.ru/integration/api/inspections) · [Взыскания](https://checko.ru/integration/api/enforcements) · [Контракты](https://checko.ru/integration/api/contracts) · [История](https://checko.ru/integration/api/timeline) · [Федресурс](https://checko.ru/integration/api/fedresurs) · [ЕФРСБ](https://checko.ru/integration/api/bankruptcy-messages)

```powershell
go run ./cmd/agent -json "Какие налоговые правонарушения ФНС опубликовала по ИНН 7707477834?"
go run ./cmd/agent -json "Покажи недавние арбитражные дела ООО с ИНН <ИНН из вашей выборки> в роли ответчика"
go run ./cmd/agent -steps 10 "Проверь контрагента с ИНН <ИНН из вашей выборки> по всем включённым источникам"
```

Ищи факты и источники в `records`, состояние запроса в `findings`. `not_loaded` означает, что выпуск ещё не загружен. `unavailable` означает, что поставщик не смог вернуть проверяемую страницу или достигнут лимит. В карточке CLI ссылки ФНС имеют вид `[fns-N]`, ссылки «Чекко» — `[checko-N]`. Когда API возвращает ссылку на карточку дела или контракта, она доступна в `record_url`.

Полную бухотчётность конкретного ООО можно бесплатно скачать вручную в [ГИР БО](https://bo.nalog.gov.ru/). CLI берёт основные строки через бесплатную квоту «Чекко».
